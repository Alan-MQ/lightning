# Phase 2 计划：连接管理与性能优化

## 🎯 Phase 2 目标
在Phase 1真正RPC调用的基础上，添加生产级的连接管理和性能优化功能：

- 并发控制
- 客户端代理生成

## 🏗️ 详细功能设计

### 1. 连接池管理 (`pool/connection_pool.go`)

#### 为什么需要连接池？
- **现状问题**：每次RPC调用都创建新的TCP连接，开销巨大
- **解决方案**：复用TCP连接，显著提高性能

#### 设计要点
```go
type ConnectionPool struct {
    mu          sync.RWMutex
    connections map[string]*PooledConnection  // 地址 -> 连接
    maxIdle     int                          // 最大空闲连接数
    maxActive   int                          // 最大活跃连接数  
    idleTimeout time.Duration                // 空闲超时时间
}

type PooledConnection struct {
    conn      net.Conn
    lastUsed  time.Time
    inUse     bool
}
```

#### 实现功能
- **Get()**: 获取可用连接（优先复用空闲连接）
- **Put()**: 归还连接到池中
- **清理机制**: 定期清理过期的空闲连接
- **健康检查**: 检测连接是否仍然有效

### 2. 超时与重试机制 (`retry/retry.go`)

#### 核心问题
- **网络不稳定**：偶发的网络问题导致调用失败
- **服务过载**：服务暂时无法响应需要重试
- **无限等待**：没有超时控制可能导致客户端hang住

#### 重试策略设计
```go
type RetryConfig struct {
    MaxAttempts   int           // 最大重试次数
    InitialDelay  time.Duration // 初始延迟
    MaxDelay      time.Duration // 最大延迟
    BackoffFactor float64       // 退避因子
    Timeout       time.Duration // 单次调用超时
}

// 指数退避算法
// 第1次: 100ms
// 第2次: 200ms  
// 第3次: 400ms
// 第4次: 800ms (但不超过MaxDelay)
```

#### 重试条件判断
- **网络错误**: 连接超时、连接被重置 → 重试
- **服务端错误**: 500系列错误 → 重试
- **业务逻辑错误**: 参数错误、权限错误 → 不重试

### 3. 并发控制 (`limiter/rate_limiter.go`)

#### 限流的必要性
- **保护服务端**：防止客户端发送过多请求压垮服务器
- **保护客户端**：控制并发数，避免资源耗尽
- **保证公平性**：确保所有客户端都能获得服务

#### 限流算法选择

**令牌桶算法** (推荐):
```go
type TokenBucket struct {
    tokens    int64         // 当前令牌数
    capacity  int64         // 桶容量
    refillRate time.Duration // 令牌补充速率
    lastRefill time.Time     // 上次补充时间
}
```

**优点**：
- 允许短时间突发流量
- 平滑控制长期平均速率
- 实现简单，性能好

**滑动窗口计数器** (备选):
- 更精确的速率控制
- 实现复杂度较高

### 4. 客户端代理生成 (`client/proxy.go`)

#### 当前使用方式的问题
现在客户端调用很繁琐：
```go
// 繁琐的手工调用
h := &codec.Header{ServiceMethod: "Calculator.Add", Seq: 1}
args := &examples.AddArgs{A: 10, B: 20}
cc.Write(h, args)
cc.ReadHeader(h)
var reply examples.AddReply
cc.ReadBody(&reply)
```

#### 理想的使用方式
希望像本地方法调用一样简单：
```go
// 简洁的代理调用
client := NewCalculatorClient("localhost:8080")
result, err := client.Add(10, 20)
if err != nil {
    log.Fatal(err)
}
fmt.Println("Result:", result.Sum)
```

#### 代理生成方案

**方案1：运行时反射生成**
- 根据服务注册信息动态生成客户端代理
- 无需额外工具，但性能稍低

**方案2：代码生成工具** (类似protobuf)
- 解析服务定义，生成Go代码
- 性能最优，但需要额外的构建步骤

**Phase 2选择方案1**，因为更符合我们的学习目标。

2. **重试策略实现**

3. **错误分类与处理**
   - 区分可重试和不可重试的错误

### Step 3: 并发控制 (第3-4周)

### Step 4: 客户端代理 (第4-5周)

3. **使用体验优化**
   - 链式调用支持
   - 错误处理简化
